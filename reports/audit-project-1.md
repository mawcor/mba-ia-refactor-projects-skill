## Findings                                                                                                                                                                                                                                                                                                    
                                                                                                                                                                                                                                                                                                             
### [CRITICAL] Arbitrary SQL Execution / SQL Injection Vulnerability                                                                                                                                                                                                                                           
                                                                                                                                                                                                                                                                                                             
File: models.py:47-49                                                                                                                                                                                                                                                                                          
Description: A construção das consultas SQL é feita através da concatenação direta de strings brutas (ex: "INSERT INTO produtos ... VALUES ('" + nome + ...), deixando a aplicação vulnerável a ataques de Injeção de SQL. Além disso, existe um endpoint em app.py:59 (/admin/query) que permite a execução   
direta de qualquer instrução SQL pelo cliente.                                                                                                                                                                                                                                                                 
Impact: Falha de segurança gravíssima que possibilita roubo, manipulação ou até mesmo a exclusão total do banco de dados da aplicação.                                                                                                                                                                         
Recommendation: Utilizar os "prepared statements" e substituição por binding (? do módulo sqlite3) em todas as transações, bem como remover permanentemente o endpoint de query livre.                                                                                                                         
                                                                                                                                                                                                                                                                                                             
### [CRITICAL] Hardcoded Credentials / Secrets                                                                                                                                                                                                                                                                 
                                                                                                                                                                                                                                                                                                             
File: app.py:7                                                                                                                                                                                                                                                                                                 
Description: A SECRET_KEY da aplicação está declarada de modo hardcoded (minha-chave-super-secreta-123) em plain-text no código fonte.                                                                                                                                                                         
Impact: Vulnerabilidade severa que expõe o segredo do servidor e compromete a segurança de sessões de usuário e tokens criptografados.                                                                                                                                                                         
Recommendation: Extrair todos os segredos para variáveis de ambiente via um arquivo .env e realizar o seu carregamento, por exemplo, por meio do os.environ.                                                                                                                                                   
                                                                                                                                                                                                                                                                                                             
### [HIGH] Queries N+1 (N+1 Problem) / Callback Hell no DB                                                                                                                                                                                                                                                     
                                                                                                                                                                                                                                                                                                             
File: models.py:188-198 (dentro de get_pedidos_usuario e get_todos_pedidos)                                                                                                                                                                                                                                    
Description: O código executa um laço de repetição (for row in rows:) sobre os pedidos e, dentro de cada repetição, roda múltiplas queries adicionais iterando sobre a tabela itens_pedido e em seguida buscando detalhes em produtos.                                                                         
Impact: Queda de performance drástica e exponencial, uma vez que o crescimento na quantidade de pedidos causa milhares de idas desnecessárias ao banco de dados.                                                                                                                                               
Recommendation: Substituir os laços de repetição ao acessar o banco por chamadas unificadas usando os comandos JOIN do SQL, permitindo consolidar todo o retorno necessário em uma ou duas simples consultas.                                                                                                  
                                                                                                                                                                                                                                                                                                             
### [MEDIUM] Ausência de Tratamento Centralizado de Erros (Error Handling)                                                                                                                                                                                                                                     
                                                                                                                                                                                                                                                                                                             
File: controllers.py:10-12, 21-22, 60-62 (entre outros)                                                                                                                                                                                                                                                        
Description: Cada um dos endpoints contém o mesmo bloco repetitivo de try/except Exception as e, formatando a mensagem de erro da mesma forma ao invés de usar um tratador único (Error Handler global).                                                                                                       
Impact: Manutenção e consistência são prejudicadas, já que as respostas a falhas sistêmicas são geridas de maneira isolada por método.                                                                                                                                                                         
Recommendation: Remover os laços de try/except repetitivos e registrar um @app.errorhandler global capaz de formatar a resposta das exceções para a API num lugar só.                                                                                                                                          
                                                                                                                                                                                                                                                                                                             
### [MEDIUM] Lógica de Acesso a Dados Espalhada (No Repository/Model pattern)                                                                                                                                                                                                                                  
                                                                                                                                                                                                                                                                                                             
File: app.py:47-57 (reset_database), controllers.py:266-274 (health_check)                                                                                                                                                                                                                                     
Description: Instâncias diretas de cursores, chamadas ao banco e comandos de DELETE ou agregação estão vazando para instâncias que não são Modelos (app.py e controllers.py).                                                                                                                                  
Impact: Fere diretamente o princípio do MVC, pois a camada de visualização/controle torna-se dependente da mecânica do banco de dados, aumentando o acoplamento.                                                                                                                                               
Recommendation: Consolidar todas as rotinas estritas de banco nas funções equivalentes do arquivo models.py.                                                                                                                                                                                                   
                                                                                                                                                                                                                                                                                                             
### [LOW] Retornos de API Inconsistentes / Magic Numbers                                                                                                                                                                                                                                                       
                                                                                                                                                                                                                                                                                                             
File: controllers.py:18, 58, 285                                                                                                                                                                                                                                                                               
Description: A formatação de retornos transita entre ter um nó "sucesso" e um "dados", misturados arbitrariamente, bem como o uso de números mágicos literais (ex: 400, 401, 404, 500) dispersos pelo código.                                                                                                  
Impact: Prejudica a utilização e integração fluída da API pelo time de Frontend.                                                                                                                                                                                                                               
Recommendation: Construir modelos base de respostas para centralizar o formato (funções de auxílio) e referenciar as respostas com constantes de estado (ex: as constantes padrão HTTP do Python).                                                                                                             
                                                                                                                                                                                                                                                                                                             
### [LOW] Código Acoplado sem Injeção de Dependências                                                                                                                                                                                                                                                          
                                                                                                                                                                                                                                                                                                             
File: models.py:4, 24, 43                                                                                                                                                                                                                                                                                      
Description: Praticamente todos os métodos buscam a conexão com o banco acessando uma variável/função global externa get_db(), travando o estado na instância atual.                                                                                                                                           
Impact: Prejudica fortemente a elaboração de mocks na hora de testar cada funcionalidade unitariamente sem ferir o banco real.                                                                                                                                                                                 
Recommendation: Parametrizar a dependência principal do banco (ou usar as extensões adequadas, como um repositório instanciável) de forma que a conexão seja passada (injetada) para a função.
